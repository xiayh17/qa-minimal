# 模块博物馆设计规范

博物馆里每一张模块卡由三部分构成：语义化描述、属性数据、功能动画。
本规范约束前两者的人工创作方式。所有批量产出必须遵守。

## 一、语义化描述（`blurb` + `lore`）

每张卡有两层文字：

- `blurb`：一句话，≤ 40 字。说清楚它是什么。出现在卡面。
- `lore`：两到三句，≤ 120 字。说清楚它为什么在这里、和其他模块的关系。
  出现在详情弹窗。

写作规则：

1. 先说事实，再说关系。第一句永远是"它做什么"，第二句才是"它和谁配合"。
2. 用动词，不用形容词。写"把会话事件追加到 JSONL 文件"，不写"强大的持久化能力"。
3. 说人话。禁止：赋能、无缝、强大、高效、智能、一站式、生态、闭环、
   "让我们看看"、感叹号、排比三段。
4. 技术名词保持原样：`ctx.fs`、session、turn、provider 不翻译。
5. 关系必须真实：只写从 cordis.yml、源码、README 能确认的配合关系。
   拿不准就不写关系，只写事实。
6. 示例（dsh-session-persistence-jsonl）：
   - 差的："高效可靠的会话持久化解决方案，让数据永不丢失！"
   - 好的：blurb"把会话事件追加到 JSONL 文件，进程退出后还能恢复。"
     lore"L2 的记忆全靠它。agent-loop 只管写事件，落盘是这条缝的事；
     --resume 恢复会话时，读回来的也是它。"

## 二、功能动画（`anim`）

每张卡的图标位是一个 48×48 的内联 SVG 小动画，用运动表达这个模块的功能。
不是装饰，是图解：看完动画应该能猜到这个模块干什么。

### 形式约束

- 内联 SVG，viewBox="0 0 48 48"，元素 ≤ 4 个，`stroke="currentColor"`，
  颜色只来自卡片的 role 色（currentColor 继承），不许额外取色。
- 动画用 SMIL 或 CSS（transform / opacity / stroke-dashoffset），时长 2–4s，
  无限循环或往返。不许用 JS 驱动，不许用图片。
- 一个循环只讲一个动作。表达"流动"就别同时表达"旋转"。
- 幅度要小：位移 ≤ 8px，缩放 0.85–1.15 之间。优雅来自克制。
- `prefers-reduced-motion: reduce` 时静止在第一帧（CSS）或移除 animate
  元素（在注册表实现里统一处理，单个动画不用管）。

### 设计方法

先写一句"它的功能像什么"，再把那个画面压缩成 2–3 个形状的运动：

- dsh-llm（流式输出）：三个点依次亮起，像 token 一个一个蹦出来
- dsh-llm-retry（重试）：一支箭头画圆弧，走到 3/4 处弹回重走
- dsh-tool-bash（终端）：`>_` 提示符，光标闪烁，行尾偶尔多一个字符
- dsh-fs-sandbox（沙箱边界）：虚线方框，一个点撞上去被弹回
- dsh-compaction-basic（折叠）：四条横线收拢成一条
- dsh-subagent（委派）：一个节点分出两条线，各自亮一下
- dsh-schedule（定时）：钟面上一根针走一格，停，再走一格

### 注册表

动画统一放在 `web/app.js` 的 `ANIMATIONS` 注册表：`{ "stream-dots": {svg:
"..."} , ... }`。卡片按 curated.json 里的 `anim` 字段引用。相同功能的模块
可以复用同一个动画（如两个审批类插件都用同一个门闩动画），但必须说明
复用理由。

## 三、检查单（批量产出时逐条过）

- [ ] blurb ≤ 40 字，第一句是事实
- [ ] lore ≤ 120 字，关系真实可查
- [ ] 无形容词堆砌、无排比、无感叹号
- [ ] 动画 ≤ 4 个元素、单一动作、幅度克制
- [ ] currentColor 取色，循环 2–4s
- [ ] 动画能回答"它像什么"
